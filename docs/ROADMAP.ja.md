# 🗺️ Luma — Roadmap

> Rust + Smithay (Wayland) によるデスクトップ環境
> アイデンティティ: Golden Hour (coffee / coral / honey / sage)
> 目標: v1.0をポートフォリオとして公開 · 期間 約2年 · surprise drop
>
> スコープ: Luma = デスクトップ環境。任意のディストロで動作する。
> Lumina OS (独自ディストロ、独自OSインストーラー付き) は
> 別プロジェクトであり、独自のロードマップを持つ。このファイルには含めない。

  できるまで無効化)
  · trait Widget (render + tick_interval + tick) をluma-widget
    クレートに実装 · name→builderの登録をlumaクレートに実装 ·
    RenderCtx ホスト対応 (Panel { height } / Desktop) ·
    layout.tomlを設定ファイルとして使用 ([[widget]] にtype、
    placement、config)
  · POC: LabelWidget (固定テキスト) と CounterWidget (1/秒)
  · redrawハンドラー内のインラインtickループ、OSDやトーストの
    elapsed-checkと同じ方式
  · 2つのホスト: パネルの列 + デスクトップ上の自由配置
    (z=5、ウィンドウの背面)
  · 移行完了: Cargo workspaceモノレポ、3クレート
    (luma、luma-theme、luma-widget)。「ウィジェット後に移行」
    というメモは完了済み

    編集モードなしではユーザーがウィジェットを追加/移動/削除する
    手段がない — layout.tomlを手動編集するしかなく、それは開発者
    体験であってユーザー体験ではない。編集モード完成時に
    state.rsの1行をアンコメントするだけで有効化可能。

### 進行中
- 🔨 コンテキスト型カスタマイズ (純粋Mintスタイル) — 設計フェーズ中
  「汎用編集モード」から改名。決定: 100%Mint/Cinnamonスタイル、
  モードなし。設定は問題のある場所で直接右クリック、Cinnamonと同じ。
  休眠中のウィジェットシステム (H59) を有効化する。H番号はファティア
  ごとに割り当て。

  なぜ純粋Mint (KDEとのハイブリッドではなく):
  · MintはLumaのアイデンティティの4本柱の1つ (Windows 7メニュー
    + Linux Mintカスタマイズ + COSMIC技術 + PCDデザイン)
  · PCD: モードなし = 摩擦なし。右クリックで解決、モードの出入りを
    覚える必要がない
  · KDEスタイルの「ウィジェットハンドル」(編集モードのハロー) は
    廃止。PCD意図は移行: 右クリックメニューは項目が大きく、
    コントラスト強、ヒットターゲット ≥ 40px

  動作方法 (Cinnamonモデル):
  · パネルで右クリック → ウィジェット追加、パネル設定などのメニュー
  · デスクトップで右クリック → ウィジェット追加、デスクトップ
    カスタマイズ、壁紙/プリセット変更
  · ウィジェットで右クリック → そのウィジェットの設定、移動、削除
  · 出入りする「編集モード」は存在しない

  影響 (忘れないように記録):
  · デスクトップコンテキストメニューのdim項目'Modo de edição'は
    有効化ではなく削除 — このフェーズのタスクの一部
  · 中期にあった「タスクバーのコンテキストメニュー」はこのフェーズに
    吸収 (パネルの右クリックが設定の入口になった)
  · 旧ファティア「モードはデスクトップアイコンの再配置のみ」は廃止
    — Mintスタイルではユーザーはアイコンをそのままドラッグするだけ

  提案ファティア (設計チャットで精査可能):
  1. 右クリックメニュー (パネル、デスクトップ、ウィジェット) +
     H59の有効化。ユーザーがウィジェットの追加/移動/削除可能に
  2. カスタマイズダイアログ (インストール済みウィジェット管理、
     壁紙/プリセット変更)。ネイティブ設定画面のタブになる可能性あり
     — 設計チャットで決定
  3. パネル設定 (高さ、配置、パネルの作成/削除)

  このフェーズ完了で解放されるもの: ウィジェットシステムが休眠から
  復帰 + メニューのdim項目を削除 + タスクバーのコンテキストメニューが
  存在するようになる。

### Lumaネイティブアプリ
> Luma独自のプログラム、Golden Hourアイデンティティ付き。
> それぞれがプロジェクト内プロジェクト — 一度に1つずつ、
> DEの基盤が成熟してから。
- ファイルマネージャー (最重要 — デスクトップフォルダーを開く、
  ナビゲート、コピー/移動)
- スクリーンキャプチャツール (画面、ウィンドウ、自由領域の
  切り取り、注釈付き。MacのCmd+Shift+5 / Windowsの切り取り&
  スケッチスタイル。高優先度: まともなDEには必須、ファイル
  マネージャーの直後に実装)
- テキストエディター
- 画像ビューアー
- 電卓
- 独自ターミナル (オプション — 現在はシステムのものを使用)
- タスクマネージャー (フルシステムモニター: プロセスリスト、
  フリーズアプリの強制終了、CPU / メモリ / ディスク / ネットワーク
  タブ。将来のアイデアにある「システムモニター」ウィジェットと
  /proc読み取りを共有 — ウィジェットはパネル上のクイック確認、
  アプリはフル機能版。低優先度、ネイティブアプリの最後尾、
  ファイルマネージャーの後)
- ソフトウェアセンター (COSMIC Storeモデル、独立ストアではない)
  → Golden Hourテーマのグラフィカルショーケースでアプリの検索、
    インストール、更新、削除が可能
  → 内部では既存のものを使用: FlathubにはlibflatPak、システム
    パッケージにはpackagekit。Lumaはホスティングなし、
    モデレーションなし、独自インフラなし
  → 直接の参考: cosmic-storeはRust製でオープンソース、
    System76の実装を研究可能
  → 大規模アプリ、低優先度、v1.0をブロックしない (当初は
    ターミナルと同様、任意のソフトウェアセンターを使用)
- 設定センター (「中期」に既出)

### インフラ / 技術
- DRMバックエンド (別のコンポジター外で実行)
  → 解放: 真のウィンドウ角丸、ネイティブマルチウィンドウ
  → さらに解放: VRRおよびリフレッシュレート混在マルチモニター
    (Gamingの Tier 2) — これらはゲーマーにとって基本中の基本。
    つまりDRMは見た目以上に優先度が高い: 「角丸」だけではなく、
    ゲーマーコミュニティが求めるものの半分を解放する。中期の
    優先度を上げる。
- HiDPI / スケーリング — 画面をぼかさないフラクショナル
  スケーリング。優先度: ゲーマー (高解像度モニター) とPCD側
  (高密度での可読UI) を同時にカバー。同じ作業、2つの対象者。
  壊れたまま出荷は不可。
- GTK/Qtテーマ生成 (サードパーティアプリがGolden Hourを採用)
- モノレポ (Cargo workspace) への移行 — ✅ H59で完了。
  現在のLumaは3クレートのモノレポ: luma、luma-theme、
  luma-widget。決定と移行時期を記録するためメモを維持。

### Gaming (単一フェーズ — 「ゲームの邪魔をしない」)
> ゲームサポート。単一フェーズに収まる、巨大ではない。本質的には
> コンポジターが邪魔をしないことを学ぶこと。Smithayは大部分の
> ブロック (direct scanout、DRMバックエンドでのVRR、tearing) を
> 既に提供 — ゼロから発明するよりも接続するだけ。
> 位置: タスクバーとDEコアが安定した後。初期v1.0に必須ではない。
> ただしTier 1はコード量が少なく効果が大きいため早期に入れられる。
>
> 優先度 — 声が大きいものが罰せられるものとは限らない。HDRは
> 最も声の大きい要望だが、最も難しく、v1でHDRがないことで新しい
> DEを非難する人はいない。一方VRR、フラクショナルスケーリング、
> マルチモニターは基本中の基本: 欠けていたり壊れていたりすると、
> ゲーマーは10分テストして去る。これらは壊れたまま出荷不可。
> HDRはv2の目玉機能、surprise dropの見出しとして温存。

**Tier 1 — 必須 (これなしではLumaはゲームに不向き):**
- フルスクリーン時のdirect scanout — ゲームのバッファが
  ハードウェアに直接送られ、Lumaは中間コピーなし
- Idle inhibit — ゲーム実行中に画面がオフにならないWayland
  プロトコル (例: コントローラーでRedMをプレイ中、キーボードに
  触れない場合)。典型的なバグ、修正コスト低
- 自身のエフェクト無効化 — フルスクリーンゲームを検出したら
  アニメーション、ブラー、シャドウをカット。GPU浪費を停止

**Tier 2 — 重要、後からでも可:**
- VRR (adaptive sync) — FreeSync/G-Sync用のモニター別トグル。
  スタッターを解消。DRMバックエンドに依存
- リフレッシュレート混在マルチモニター — 144Hzと60Hzを同時に
  使用してもシステムが低い方に固定されない。DRMバックエンドに依存
- Tearing control — wp_tearing_controlプロトコル、ゲームが
  最小レイテンシのために非同期プレゼンテーションを要求
  (競技ゲーム向け)

**Tier 3 — 贅沢、かなり後:**
- バーのGameModeステータス (装飾、オプション)
- HDR — v1には複雑すぎて新しすぎる。v2の目玉機能として温存:
  コミュニティで最も声の大きい要望であり、Linuxに来た人の
  不満第1位。見出しのために意図的に温存

### v1.0への道

**システム画面 (セッション周りの「chrome」):**
> KDEと同様、Lumaはこれらをテーマ変更可能なコンポーネントとして
> 扱い、ネイティブ設定画面の単一パネルで全て設定可能。
> ディスプレイマネージャーを構築するのではなく、SDDMにテーマを
> 適用する。
- セッションファイル (.desktop) — SDDM / GDM / 任意の
  ディスプレイマネージャーのリストにLumaを表示させる。些細だが、
  これなしでは誰もLumaにログインできない。v1.0必須。
- SDDMテーマ (Golden Hour) — ログイン画面。KDEと同様のSDDM用
  QMLテーマ。決定: ゼロからgreeterを書かない; 既存のSDDMに
  テーマを適用する。ポリッシュ。
- スプラッシュスクリーン — ログイン後DE読み込み中の短い画面
  (KDEのKSplash)。Luma描画、軽量、ブランディングの瞬間。
  ポリッシュ、低優先度。
- ブートテーマ (Plymouth) Golden Hour — グラフィック + 小さな
  設定のみ、何も構築しない。低コストのポリッシュ、高いリターン。

- Lumaのパッケージングとインストール — DEがユーザーの
  マシンに届く方法。カバー: ソースコードのビルド手順 +
  ディストロパッケージ (Arch用AUR、Fedora用COPR、Ubuntu用.deb)。
  surprise drop必須 — これなしではr/linux、Phoronix、HNの
  ユーザーがリポジトリを開いてもテストできない。セッションファイルと
  対になる。(LumaはDE: Flatpakにはならない、Flatpakはアプリ用、
  DEはシステムにインストール。)
- 全般的なポリッシュ、完全QA
- 4つのビジュアルプリセット: Classic、Mint、Dock、PCD Max
- 最終ドキュメント
- Surprise drop: Diolinux、r/linux、Phoronix、Hacker News

## 💭 将来のアイデア (基盤完成後、忘れないために記録)
> Mac/Windowsに触発されたDEに適した機能。優先度ではない —
> 基盤とネイティブアプリの後にのみ取り組む。
- グローバル検索 (Spotlightスタイル) — アプリ、ファイル、設定を
  一箇所で検索。既存のメニュー検索を拡張。
- ウィンドウスナップ — 端にドラッグするとウィンドウが半画面に
  スナップ。生産性機能。
- 時間による自動ダーク/ライトモード — テーマが日没に連動。
  Golden Hourアイデンティティに合致、Lumaのテーマ的差別化要素。
- ユーザーカスタマイズ可能なキーボードショートカット。
- ファイルプレビュー — デスクトップ上のファイル選択時のプレビュー。
- サムネイル付きウィンドウスイッチャー — Alt+Tabでアイコンだけ
  でなく各ウィンドウのプレビューを表示。
- ウィンドウ概要 — MacのExpose/Mission Controlスタイル、
  全ウィンドウを画面に展開して選択。
- クリップボード履歴 — Win+V、最近コピーしたアイテムを保持。
- ホットコーナー — マウスを角に移動するとアクションを実行
  (デスクトップ表示、メニューを開くなど)。
- Night light — 夜間に画面色温度を暖色化。Golden Hour
  アイデンティティに合致、自動ダークモードと同様。

## 🎯 プロジェクトの原則
- 一度に1ステップ、次に進む前に完了しテスト済み
- 未完成のシステムに依存する機能 = dim項目 + DEBTにメモ
- ハードコードされたhex値ゼロ — 全てtheme.tomlに
- アトミックコミット、各コミットはコンパイル・実行可能
- 各ステップ前にバックアップタグ
- PCDアクセシビリティ: ヒットターゲット ≥ 40px、WCAG AA
