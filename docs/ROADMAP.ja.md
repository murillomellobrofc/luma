# 🗺️ Luma — ロードマップ

> Rust + Smithay (Wayland) によるデスクトップ環境。
> アイデンティティ: Golden Hour (coffee / coral / honey / sage)。
> 目標: ポートフォリオとしての v1.0 · 約 2 年のタイムライン ·
> サプライズドロップ。
> スコープ: Luma = デスクトップ環境、どの distro でも動く。
> Lumina OS (独自 distro、独自 OS インストーラー付き) は別プロジェクト
> で、独自のロードマップを持つ。このファイルには含めない。

### 中期

- **通知フェーズ 2:** スタッキング、アプリごとのグループ化、
  センター/履歴
- **設定可能なウィジェットシステム** (KDE Plasma スタイル)
  → ユーザーがパネルやデスクトップに追加/削除/設定するウィジェット
    (時計、天気、メモ、システムモニター等)
  → 決定: ウィジェットは Rust の Luma-native、luma-bar 自身が
    レンダリング。GTK でも Qt でもない。KDE のプラズモイドと同じで、
    プラズモイドは差し込み可能な Qt アプリではない。自分たちで
    レンダリングしてこそ Golden Hour + hit target ≥ 40px が保証
    できる。GTK/Qt は別経路で Luma に入る: サードパーティアプリは
    ウィンドウとして (Wayland)、トレイは SNI 経由、そして GTK/Qt
    テーマの生成。
  → 大きな基盤的アーキテクチャ — ロードマップの最大のステップの
    一つ。DE のベースが成熟してから取り組む。
  → アンロック: タスクバーのメニュー + 一般編集モード
- **Luma の一般編集モード** (KDE スタイル、統合)
  → ユーザーが一箇所ですべてを整理するモード: デスクトップアイコン
    の再配置 AND パネルのウィジェット/レイアウト操作
  → デスクトップアイコン (✅ 既存) + ウィジェットシステム
    (❌ まだ) に依存 — なのでウィジェットと一緒/後に来る
  → コンテキストメニューの dim 項目「Modo de edição」を点灯させるもの
  → ロードマップの 3 項目を 1 つに統合: メニューの dim 項目 +
    ウィジェットシステム + この一般編集モード

  **動作:**
  · コンテキストメニューの「Modo de edição」項目 + キーボード
    ショートカットで入る; 「完了」ボタンか Esc で出る (すべて
    再ロック)
  · 画面に薄いオーバーレイがかかり、パネル/ウィジェットがハイライト
    枠を持ち、上部に「ウィジェット追加」と「完了」のバー
  · 可能なこと: デスクトップアイコンの再配置 · ウィジェットの
    追加/移動/削除/設定 (デスクトップとパネル) · パネルの調整
    (高さ、配置、固定/フロート、新規作成) · 壁紙とプリセットの変更

  **ウィジェットのハンドル — PCD の差別化要素:**
  · フォーカスされた各ウィジェットはボタン付きハンドルを表示
    (設定、移動、リサイズ、削除)
  · KDE ではこれらのハンドルは小さくて煩わしい — Luma では
    hit target ≥ 40px、大きなボタン、Golden Hour カラー
  · KDE の「回転」を切る (誰も使わない)
  · 振戦や弱視のある人が使える編集モード = PCD Max の実践的な物語

  **スライス (それぞれビルドして単独で実行可能):**
  1. デスクトップアイコンの再配置のみのモード (ベース既存)
  2. ウィジェットの追加/移動/削除/設定
  3. パネル編集 (高さ、配置、パネル新規作成)

- **タスクバーのコンテキストメニュー** (ウィジェット依存)
- **Luma ネイティブの設定画面** (システム画面のテーマページを含む:
  スプラッシュ、ログイン/SDDM、ブート — KDE の「色とテーマ」と
  同じく単一パネル)
- **画面設定** (解像度、モニター)
- **バッテリーアプレット内の輝度スライダー** (独立アプレットでは
  なく、KDE と同じくバッテリーと一緒に。バックエンドは既存で、
  輝度 OSD がそれを証明している; クリック可能なシェルだけが必要。
  バックライトがある時のみ表示、バッテリーと同じロジック)

### Luma のネイティブアプリ

Golden Hour のアイデンティティを持つ Luma 独自のプログラム。
それぞれ実質的にプロジェクト内プロジェクト — 一つずつ作る、
DE のベースが成熟してから。

1. **ファイルマネージャー** (最重要 — デスクトップのフォルダを開く、
   ナビゲート、コピー/移動)
2. **スクリーンショットツール** (画面、ウィンドウ、自由領域の
   切り取り、注釈付き。Mac の Cmd+Shift+5 / Windows の切り取り
   ツールスタイル。優先度高: まともな DE はすべて持っている、
   ファイルマネージャーのすぐ後に作る)
3. **テキストエディタ**
4. **画像ビューア**
5. **電卓**
6. **独自ターミナル** (オプション — 今はシステムのを使う)
7. **タスクマネージャー** (完全なシステムモニター: プロセス一覧、
   ハングしたアプリのキル、CPU / メモリ / ディスク / ネットワーク
   タブ。将来のアイデアの「システムモニター」ウィジェットと /proc
   読み取りを共有 — ウィジェットはパネル上の素早い視認、アプリは
   完全版。低優先度、ネイティブアプリ列の最後、ファイルマネージャー
   の後)
8. **ソフトウェアセンター** (COSMIC Store モデル、独立ストアではない)
   → アプリの検索、インストール、更新、削除のための Golden Hour 顔
     のグラフィックショーケース
   → 内部は既存のものを使う: Flathub には libflatpak、システム
     パッケージには packagekit。Luma は何もホストせず、モデレート
     せず、独自インフラを持たない
   → 直接の参照: cosmic-store は Rust のオープンソース、System76 が
     どうやったか研究できる
   → 実質的なアプリ、低優先度、v1.0 をブロックしない (最初は
     ユーザーは今のターミナル同様、任意のソフトウェアセンターを
     使う)
9. **設定センター** (「中期」にすでに記載)

### インフラ / 技術

- **DRM バックエンド** (他のコンポジターの外で実行)
  → アンロック: 本物の角丸、ネイティブマルチウィンドウ
  → 同時にアンロック: VRR と混合リフレッシュのマルチモニター
    (Gaming の Tier 2) — そしてこれらはゲーマーの主食。
    つまり DRM は見た目以上の優先度を持つ: 単なる「角丸」では
    なく、ゲーミングコミュニティが要求するものの半分を解放する。
    中期キューで順位を上げる。
- **HiDPI / スケーリング** — 画面をぼかさない fractional scaling。
  優先度: ゲーマー (高解像度モニター) AND PCD 側 (高密度で
  読みやすい UI) を同時にサービス。同じ作業、2 つの観客。壊れた
  まま出してはいけない。
- **GTK/Qt テーマの生成** (サードパーティアプリが Golden Hour を採用)

### Gaming (単一フェーズ — 「ゲームの邪魔をしない」)

ゲームサポート。単一フェーズに収まる、モンスターではない。
根本的にはコンポジターが脇に退くことを学ぶこと。Smithay は
ほとんどのブロックをすでに提供している (direct scanout、DRM
バックエンドでの VRR、tearing) — ゼロから発明するより配線をつなぐ
感じ。位置: タスクバーと DE のコアが堅固になってから。初期 v1.0 に
必須ではない。ただし Tier 1 は早めに入れられる、コードが少なく
得られるものが大きいから。

優先度 — 人々が大声で求めるものは、なければ罰されるものではない。
HDR は最も騒がしい要求だが最も難しく、新しい DE が v1 に HDR が
ないことで叩かれることはない。一方 VRR、fractional scaling、
マルチモニターは主食: 欠けたり壊れていたら、ゲーマーは 10 分
試して去る。これらは壊れたまま出してはいけない。HDR は v2 の
スター、サプライズドロップの見出し用に取っておく。

**Tier 1 — 必須 (これがないと Luma はゲームに向かない):**
- フルスクリーンでの Direct scanout — ゲームのバッファが直接
  ハードウェアへ、Luma が間でコピーしない
- Idle inhibit — ゲーム実行中に画面がブランクするのを防ぐ Wayland
  プロトコル (例: コントローラーで RedM をキーボードに触れずに
  プレイ)。古典的なバグ、解決は安価
- 自身のエフェクトをオフ — フルスクリーンゲームを検出したら、
  アニメーション、ブラー、シャドウをカット。GPU の無駄遣いを停止

**Tier 2 — 重要、後でも可:**
- VRR (adaptive sync) — FreeSync/G-Sync 用のモニター別トグル。
  スタッターを殺す。DRM バックエンド依存
- 混合リフレッシュのマルチモニター — 144Hz と 60Hz を一緒に、
  システムが遅い方に全部クランプしない。DRM バックエンド依存
- Tearing control — wp_tearing_control プロトコル、ゲームが最小
  遅延の非同期プレゼンテーションを要求 (競技ゲーム)

**Tier 3 — 贅沢、もっと後で:**
- バーの GameMode ステータス (装飾、オプション)
- HDR — v1 には複雑すぎて新しすぎる。v2 のスターに:
  コミュニティで最も騒がしい要求、Linux に来る人の不満 No.1。
  見出し効果のために意図的に保留

### v1.0 へ向けて

**システム画面 (セッションを取り囲む「クロム」):**
KDE と同じく、Luma はこれらをテーマ可能なコンポーネントとして
扱い、すべてネイティブ設定画面の単一パネルで設定可能。display
manager は構築しない — SDDM をテーマ化する。

- **セッションファイル (.desktop)** — SDDM / GDM / 任意の display
  manager のリストに Luma を表示。些細だが、これなしには誰も Luma
  にログインできない。v1.0 必須。
- **SDDM テーマ (Golden Hour)** — ログイン画面。KDE がするように
  SDDM 用の QML テーマ。決定: 独自 greeter をゼロから書かない;
  既存の SDDM をテーマ化。Polish。
- **スプラッシュ画面** — ログイン後 DE が読み込まれる間の素早い
  画面 (KDE の KSplash)。Luma レンダリング、軽量、ブランドの瞬間。
  Polish、低優先度。
- **ブートテーマ (Plymouth) Golden Hour** — グラフィックと小さな
  config のみ、何も構築しない。安価な polish、高リターン。
- **Luma のパッケージングとインストール** — DE が人々のマシンに
  届く方法。カバー範囲: コードのビルド手順 + distro パッケージ
  (Arch には AUR、Fedora には COPR、Ubuntu には .deb)。サプライズ
  ドロップ必須 — これなしには r/linux、Phoronix、HN の人々がリポを
  開いてもテストできない。セッションファイルと対をなす。(Luma は
  DE: Flatpak にはしない、Flatpak はアプリ用、DE はシステムに
  インストールする。)
- **一般的な polish、完全な QA**
- **4 つのビジュアルプリセット:** Classic、Mint、Dock、PCD Max
- **最終ドキュメント**
- **サプライズドロップ:** Diolinux、r/linux、Phoronix、Hacker News

## 💭 将来のアイデア (ベース後、忘れないようにメモ)

DE に収まる mac/Windows 触発の機能。優先ではない — ベースと
ネイティブアプリの後に入る。

- **グローバル検索 (Spotlight スタイル)** — アプリ、ファイル、設定
  を一箇所で検索。既存のメニュー検索を拡張。
- **ウィンドウスナップ** — エッジへドラッグでウィンドウを半画面に
  スナップ。生産性機能。
- **時刻による自動ダーク/ライトモード** — テーマが日没を追う。
  Golden Hour のアイデンティティに合い、Luma のテーマ的差別化に
  なる。
- **ユーザーカスタマイズ可能なキーボードショートカット。**
- **ファイルプレビュー** — デスクトップのファイル選択時のプレビュー。
- **サムネイル付きウィンドウスイッチャー** — アイコンだけでなく
  各ウィンドウのプレビューを表示する Alt+Tab。
- **ウィンドウ概要** — Mac の Exposé/Mission Control スタイル、
  画面上のすべてのウィンドウを広げて選択。
- **クリップボード履歴** — Win+V、最後にコピーしたアイテムを保持。
- **アクティブコーナー** — マウスを角に投げてアクション発動
  (デスクトップ表示、メニューを開くなど)。
- **Night light** — 夜に画面の色が暖かくなる。自動ダークモード
  同様、Golden Hour のアイデンティティに合う。

## 🎯 プロジェクトの原則

- 一度に一つのステップ、次に進む前に完了してテスト
- 準備のないシステムに依存する機能 = dim 項目 + DEBT へのメモ
- ハードコードされた hex はゼロ — すべて theme.toml に
- アトミックなコミット、それぞれがビルドして実行
- 各ステップ前にバックアップタグ
- PCD アクセシビリティ: hit target ≥ 40px、WCAG AA
